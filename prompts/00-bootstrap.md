# 阶段 00：环境、边界与契约

请实际检查当前目录、现有文件、Git 状态、操作系统/架构、Node/npm、Docker CLI 与 daemon、端口和客户端权限。不要假设空目录或已经装好依赖，不要覆盖已有工作。

读取 AGENTS.md 与 docs/PRODUCT_SPEC.md。先确认原生 subagent 可用性、工作目录共享情况。可用时派出以下三个只读工作 agent：

A 教学设计：审查十题顺序与 Java 前置依赖，给出 704、206 的学习步骤和可观察完成标准。
B 运行与安全：核对本机 Java 容器执行可行性，设计输入输出、限制、失败与清理路径。
C 架构与测试：提出最小目录结构、契约、关键反例和阶段验收依赖。

这轮不要让它们各自改根配置。主 agent 汇总并做决定，避免输出三个相互矛盾的方案。

创建：
- docs/ENVIRONMENT.md：真实检查结果、可用/缺失依赖、权限与阻塞，不打印敏感环境变量。
- docs/ARCHITECTURE.md：最终采用的简单架构、参考演示与真实执行的分离、数据流。
- docs/CONTRACTS.md：Lesson、RunRequest/RunResult、ReferenceTrace、Progress 的字段、状态、示例和不变量；逐题方法签名、序列化与判定规则。
- docs/TASKS.md：00—06 的依赖、文件所有权、验收条件与执行顺序。
- docs/DECISIONS.md：方案选择与未采纳方案的简短原因。
- docs/STATUS.md：本轮结果、已确认事项、阻塞、下一阶段入口。

固定技术选择和题目集沿用 PRODUCT_SPEC，不比较十种框架，也不生成十个空题目页面。不要在本阶段开始大规模业务编码。

验收：契约明确了真实执行/参考模型两种来源；704、206、283、1、104 等不同返回/修改语义均有定义；并行写入没有共享文件争用；环境缺失得到诚实记录。

完成后给出实际工作 agent 交付摘要、创建的文件和阶段 01 入口，然后停止。
