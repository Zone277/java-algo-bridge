# 阶段 05：独立审查、修复与学习体验

本阶段不加新题、不引入 AI API、不重构到新框架。启动最多三个独立审查 agent，主 agent 控制修复文件所有权。

A 教学与算法审查：逐题检查 Java 语义、前置知识、不变量、复杂度说明、参考状态与代码映射、错误案例、输入边界；亲自提出至少一个之前未使用的反例或有效随机检查。特别检查引用赋值、283 的 void、1 的索引顺序、3 的子串和重复字符。
B 执行安全审查：核对实际 Docker 配置和资源约束，不只看提示词；检查 shell 注入风险、路径、宿主机挂载、联网、非 root、超时清理、大输出、并发隔离、Host/Origin、Docker 缺失和服务退出。只用受控的本地测试，不执行破坏性宿主机测试。
C 前端与端到端审查：真正打开网站走完整流程，检查键盘操作、聚焦、可读字号、布局、长代码/错误、播放前后退、输入切换、预测反馈、草稿/进度恢复、旧请求结果、API 失败和无 Docker 的提示。

审查先产出缺陷：严重度、文件/位置、复现步骤、预期与实际、修复建议。不能只说“总体良好”。独立 agent 不应同时修改实现者仍在写的文件；主 agent 排程修复并复测。

补齐关键回归：参考解法默认折叠；guided 与 independent 草稿不同；查看解法标记保留；本地存储不可用时可继续临时练习；核心素材不从 CDN 加载；执行结果只匹配其提交时源码版本。

实现/完成 test:e2e 与 verify。对 704、206、3 跑完整的真实 Java 端到端路径，其他题跑真实运行冒烟；不能拦截关键判题接口返回预制成功。

交付 docs/REVIEW.md，逐项列出发现与处理结果。所有阻断问题修复并验证后才算本轮通过；缺依赖导致无法验证的部分诚实记为 BLOCKED。更新 STATUS 后停止。
