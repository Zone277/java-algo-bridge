# 阶段 02：第 704 题的完整教学闭环

目标不是增加题目数量，而是把“一个不会 Java 的目标用户如何学完一题”做完整。

先读现有规则、规范、契约和状态。主 agent 保证共享接口稳定，然后并行委派：
A 课程 agent：只写第 704 题课程包及局部测试，产出必要 Java 微知识、原创题面、手工模拟、搜索区间不变量、逐步推导、starter、Java 参考代码、三层提示、两处预测、引导任务、至少 8 个有效用例和两个典型错误夹具。
B 可视化 agent：只写 packages/visualizer 与授权的 704 参考状态模型路径，实现确定性快照、数组区间、left/right/mid、变量表、代码步骤映射以及播放/回退/重置。主 agent 明确划分 A/B 的路径，不能让它们同时写 704 同一个文件。
C 前端 agent：只写 apps/web 的学习流程、微课卡、预测互动、引导/独立模式切换、提示、真实反馈与本地草稿/进度。

必须让学生先看到：方法签名如何对应输入输出，int[] 和 length 如何使用，while 条件与 left/right 更新如何落到 Java 代码上。

演示统一标注“参考解法 · 算法状态演示（非 JVM 调试）”，展示的是参考代码对应步骤，不是学生编辑代码的虚构调试轨迹。输入切换应生成新轨迹；每个视图读取同一不可变快照。

预测题先提交选择或值再揭示状态，答错给出解释。引导模式至少分三步逐渐减少代码支架，最终通过真实 Java runner 检查；独立模式从方法骨架开始，不自动塞入完整解法。

参考模型最终输出与真实 Java 参考代码在固定用例及固定随机种子的有效小输入上比较；另测区间缩小、左右边界与 mid 范围等中间不变量。最终输出相同不能替代中间状态检查。

本轮验收：完成一次从路线页进入 704、阅读语法、预测、播放/后退、补全、独立编辑、运行失败、修正、通过本站测试、刷新后恢复草稿的真实端到端流程。不能用接口拦截造出通过结果。

把课堂操作截图/测试报告、真实命令和已知问题记录下来。不要把“访问页面”和“看了答案后的通过”记为独立掌握。修复之后停止，尚不扩题。
