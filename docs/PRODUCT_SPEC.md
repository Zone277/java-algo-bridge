# Java Algo Bridge：固定产品规格 v1

## 1. 目标

这是待验证的目标用户假设，不是对全部在校学生的概括：学习者接触过 C 和数据结构理论，但难以将概念转为 Java 代码。

产品要支持的最短学习闭环是：补齐必要语法 → 读懂任务与输入输出 → 预测状态 → 理解参考算法 → 在支架下编写 → 独立编写 → 真实执行并解释错误。

当前成功的工程标准不是“有二十八个题目卡片”，而是二十八题都能经过上述流程。学习效果仍需真实学生试用验证，不能用自动化测试通过来代替。

## 2. 包含与不包含

包含：中文界面，Java 21，下面固定的 28 题；8 个短 Java 桥接单元；在线编辑器；本地真实 Java 编译执行；参考算法状态演示；分级提示；本地草稿、进度与恢复；自动化测试与本机启动说明。

不包含：账号、登录、支付、排行榜、讨论社区、移动端原生 App、多语言、课程视频、AI 聊天或 agent 产品服务、云部署、复杂数据库、通用 JVM 调试器、完整生产级 OJ、反作弊系统。

首次安装依赖、镜像与测试浏览器可能需要联网。安装完成后，核心应用流程应不依赖云服务或 CDN；须实际验证后才标记离线运行已验证。

## 4. Java 桥接单元

J1：从 C 函数到 Java 方法；class Solution；参数与返回；平台为什么可以不要求学生写 main；展示只读调用器解释。
J2：int/boolean/char；局部变量初始化；分支与循环；数组 length；边界与整数运算。
J3：数组是对象；基本值与引用值；new；别名；数组原地修改与重新赋值的区别。
J4：String.length()、charAt()、equals()；char 与字符串的区别；本课程字符串输入范围，避免宣称 char 总等于一个完整 Unicode 字符。
J5：集合的最小使用集；泛型中的 Integer/Character；HashMap 查找/写入；HashSet；ArrayDeque 的栈操作与空值检查。
J6：ListNode 类；对象身份；next 字段；null；引用赋值和对象修改；按值传递引用值。
J7：TreeNode；递归基例、递归调用、返回；调用栈与对象图的区别。
J8：如何读编译错误、运行异常、错误结果与超时；构造反例；使用输入输出说明自己的思路。

每单元有清晰目标、一段 C 已知知识对照、正确 Java 示例及至少一个预测或填空互动。只讲当前二十八题会用到的内容，不扩成整本 Java 教材。
微课的静态预测/填空检查必须标明性质；真正的代码运行练习复用题目编辑器与 Java 执行通道，不另造假解释器。

## 5. 每题课程包

每题课程包至少有：

- id、slug、名称、学习顺序、来源、任务语义、本站输入限制和前置单元。
- 具体学习目标、原创题面、输入输出解释、手工模拟。
- 一个能讲清楚的初始办法，以及为何需要本题的目标算法；不是每题都机械套用“暴力→最优”。
- 目标算法的不变量/状态含义、边界、复杂度说明。
- 学生 starter.java、干净且可编译的参考 Java 解法、稳定代码步骤映射。
- 参考状态模型、可视化配置、至少 2 个可切换演示输入。
- 至少 2 个状态预测检查、一个分步代码补全任务、独立编码入口。
- 三层提示：概念提示 → 数据结构或不变量提示 → 关键伪代码；完整答案单独折叠。
- 至少 3 种常见错误、触发反例与解释。
- 至少 8 个有效测试用例及解释其覆盖点；参考解法都真实执行通过。
- 至少 2 个故意错误的 Java 解法作为测试夹具，确保用例能发现典型缺陷。

参考解法默认不显示。引导练习最终提交完整 Java 源码到真实 runner 验证，不仅匹配某个参考字符串。独立模式初始只有方法骨架；与引导模式分别保存草稿。

## 8. 接口契约最低内容

阶段 00 将下列要求转换为明确 schema 和示例，再并行实现。不要让不同 agent 各自猜测。

Lesson：身份、先修、学习目标、内容步骤、starter、reference、提示、练习、版本、测试和状态模型关联。

RunRequest：problemId、source、mode（run/submit）、run 模式的已验证输入。problemId、模式和源代码大小都有白名单/上限。

RunResult：requestId、problemId、sourceHash、阶段、状态、用例结果、真实 stdout/stderr、编译诊断与学生源码行列、计时、截断与资源限制信息。请求正在运行期间编辑源码后，返回结果只属于它原来的 sourceHash，不能错误标记当前新代码通过。

状态至少覆盖：PASSED_LOCAL_TESTS、WRONG_ANSWER、COMPILE_ERROR、RUNTIME_ERROR、TIME_LIMIT、RESOURCE_LIMIT、OUTPUT_LIMIT、RUNNER_UNAVAILABLE、INVALID_INPUT、SYSTEM_ERROR。可增加 QUEUED/RUNNING/CANCELLED；不得混淆基础设施失败与学生算法错误。

ReferenceTrace：mode 固定 reference-model，problemId、algorithmVersion、referenceSourceHash、inputHash、初始状态和不可变快照序列。每个快照包含 stepId、对应代码范围、变量、结构状态、当前说明、可选预测检查点。明确快照是该步骤执行后的状态；初始快照另设。

数据结构状态采用有判别字段的联合类型，而不是到处使用 any：数组及索引、键值表、栈、链表对象图及变量绑定、树与调用栈、DP 表或滑动窗口等。

Progress：schemaVersion、problemId、lessonVersion、学习步骤、预测结果、两种模式草稿、hintsUsed、viewedSolution、guidedPassed、independentLocalPassed。课程更新后不得无提示覆盖旧草稿。

## 9. 可视化真实性

第一版允许用 TypeScript 写每道预置参考算法的纯状态模型，以实现无需 JVM 调试协议的交互演示。模型不是学生代码解释器，也不是 JVM 的真实逐行跟踪。

整个演示明确标记为“参考解法 · 算法状态演示（非 JVM 调试）”。不得把学生编辑器的源码放在旁边，并把参考动画伪装成该源码的实际执行轨迹。学生源码另走真实执行通道。

模型根据被验证的输入生成快照，不能只播放与输入无关的固定动画。输入或参考代码版本变化时应失效旧轨迹。

状态推进由确定性算法生成，不用动画计时器推动真实算法状态。播放器只选择快照；动画只是相邻快照间的装饰过渡。上一步必须能完整恢复，不需要推断逆算法。

节点对象有稳定 ID，值相同的不同节点不能合并。引用绑定和对象 next 字段分别表达。不要将对象从某个变量不可达直接画成已被 GC 回收。

对所有给定用例和固定随机种子的有效小输入，将状态模型最终输出与实际 Java 参考代码比较；另外验证区间、不变量、链接和回溯等中间状态。仅仅输出相同不能证明动画正确。

可视化可以限制数组长度、树深度和快照数，例如初始设置数组最多 30 项、快照最多 2000 个，再根据实测调整。上限透明展示；不要无提示截断后仍声称播放完整过程。

## 10. Java 执行与判定

学生编辑完整 Solution 类及所需 import，不要求写 main。后台保存原样的 Solution.java，并使用单独的可信调用器调用规定方法。ListNode 和 TreeNode 由独立平台文件提供，学生可以查看定义。

不得将用户字符串拼接进 shell。使用进程参数数组、固定内部文件名与经过 schema 验证的 JSON 输入；不允许用户指定命令、镜像、文件路径或适配器类。

至少支持 int 返回、boolean 返回、int[] 返回、void 原地修改、单链表输入输出、二叉树输入。字符串用标准 JSON 编解码与明确字符范围，不手写脆弱的 split 解析器。

逐题判定规则：

- 704：返回有效索引或 -1；升序且元素不重复。性能说明不能仅凭本站小样例证明。
- 283：检查调用后的原数组，非零相对顺序保持；不能只检查 void 返回。
- 977：数组内容和顺序正确，输入限制与整数平方范围匹配。
- 1：允许索引顺序交换；两个索引必须不同、合法且对应元素和等于 target；有效输入存在唯一解，不把无解混入官方语义的测试。
- 20：检查类型、嵌套和顺序，典型错误是遇到右括号时空栈、最后栈未空。
- 206：返回反向链；检测异常环和过长输出；按本站明确的结构要求验证原节点身份与 next 重连，不能让重复值掩盖节点丢失。
- 21：复用两条输入链表的节点且输出排序正确；记录节点身份，拒绝成环、丢节点或错误重复节点。
- 104：树采用明确的层序序列化与 null 标记，不混用堆索引式解释；深度按节点数，空树为 0。教学递归的深度限制透明展示。
- 70：n 范围遵循原题语义，正确处理 1、2 和较大 n；不要把 n=0 无标注加入原题判题。
- 3：连续子串而非子序列；遵循本课程字符范围，包含空串、重复字符和空格；至少用能暴露错误回退左边界的反例。

参考解法与两个错误夹具都必须真实编译执行。执行成功不代表结果正确，学生打印 PASS 不代表通过。服务端比较结构化实际结果与可信预期，不信任学生自报判定。

“通过”仅表示通过本站公布范围内的本地测试；不声称复现官方测试集合、时限、完整性能约束或反作弊能力。

## 11. 容器最低约束

每个运行/提交任务一个独立临时目录和一次性容器；仅输入目录只读挂载，编译产物写受限 tmpfs 或容器专用临时空间，容器根文件系统只读。

非 root；禁网；cap-drop ALL；no-new-privileges；默认 seccomp；CPU/内存/PID/可写空间/输出/源码/输入大小限制；没有特权模式、宿主机网络或 Docker socket。

可作为初始配置而非性能承诺的预算：1 CPU、512 MiB 内存与对应 swap 上限、128 PID、源码 64 KiB、输出 64 KiB、编译超时 15 秒、单次执行 3 秒、总任务 30 秒、并发 1 与有限等待队列。由本机实测验证 JVM 启动与编译可行性，所有调整记录原因；不能靠无限制配置掩盖缺陷。

检查实际 Docker/cgroup 环境是否实施资源限制，不能只检查命令里有没有参数。根本无法约束时标记执行环境不满足要求。

清理任务使用本项目标签与任务 ID；异常、超时、取消、Ctrl+C 后回收本项目任务。应用启动时可以清理本项目过期任务，不清理其他容器。

只监听回环接口，同时校验 Host/Origin、限制请求体，执行端点采用同源 JSON 请求及合适的本地防跨站调用措施，默认不开放跨域。不要把浏览器传来的任意地址当可信 Origin。

文档明确：这是单用户本地开发/教学工具，不是安全保证完备的生产多租户执行平台；不得直接暴露公网。
